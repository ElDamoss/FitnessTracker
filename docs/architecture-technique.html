🏗️ Architecture Technique — MuscuTrack Pro

Documentation du flux technique complet, des services utilisés, et de la procédure de suppression.

1. Vue d'ensemble

L'application est une PWA (Progressive Web App) hébergée statiquement, connectée à un backend cloud.

📱 Utilisateur (téléphone/PC) │ ▼ 🌐 Netlify (hébergement fichiers statiques) URL : cosmic-bombolone-e3e71a.netlify.app │ │ Sert : index.html + CSS + JS ▼ 🖥️ Navigateur (exécute le JS côté client) │ │ Appels API (HTTPS) ▼ 🗄️ Supabase (Backend-as-a-Service) ├── 🔐 Auth (comptes utilisateurs) ├── 🗃️ PostgreSQL (données) └── 🛡️ Row Level Security (isolation users) │ ▼ 💾 Base de données PostgreSQL ├── exercises (bibliothèque) ├── programs (programmes + jours) ├── sessions (historique séances) └── mensurations (suivi corporel)

3. Flux détaillé

3.1 Inscription d'un utilisateur

  1. L'user ouvre l'app → écran de login
  2. Clique "Créer un compte" → remplit email + mot de passe + prénom
  3. Le JS appelle sb.auth.signUp() → requête HTTPS vers Supabase Auth
  4. Supabase crée le compte dans auth.users
  5. Session JWT retournée → stockée dans le navigateur
  6. seedDefaults() ajoute les exercices manquants dans la base
  7. L'app affiche le dashboard

3.2 Connexion

  1. L'user entre email + mot de passe
  2. sb.auth.signInWithPassword() → Supabase vérifie
  3. JWT retourné → l'app charge les données de cet user uniquement (RLS)

3.3 Séance d'entraînement

  1. L'user va dans Programmes → clique "Start" sur un jour
  2. L'écran workout s'affiche (chrono, exercices, sets)
  3. Il saisit poids/reps → clique ✓ → timer repos se lance
  4. À la fin → clique "Fin" → récap affiché
  5. "Sauvegarder" → DB.addSession() → INSERT dans Supabase table sessions

3.4 Isolation des données (Row Level Security)

-- Chaque user ne voit QUE ses propres données
CREATE POLICY "Users manage own programs" ON programs
  FOR ALL USING (auth.uid() = user_id);

-- Les exercices par défaut sont visibles par tous
CREATE POLICY "Users see default and own exercises" ON exercises
  FOR SELECT USING (is_default = true OR auth.uid() = created_by);

5.1 Notes V8 (modèle de données & sécurité)

  • Type de mesure — exercises.set_measurement_type vaut reps ou seconds (défaut reps) ; les exercices en secondes stockent la valeur du set dans duration.
  • Tempo — texte libre par exercice dans le JSONB programs.days, réaffiché pendant la séance.
  • Session non permanente — le client Supabase utilise window.sessionStorage pour la session : une reconnexion est requise après fermeture du navigateur.
  • Anti-brute-force — table login_attempts + RPC check_login_gate / record_login_failure / record_login_success ; blocage après un seuil de tentatives échouées pendant une fenêtre de verrouillage.
